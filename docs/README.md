# Messenger

**Описание:** Веб-приложение на Django, которое позволяет пользователям управлять рассылками сообщений для клиентов.

## Нововведения для пользователей

1. **Управление клиентами** — добавление, просмотр, редактирование и удаление получателей рассылок с валидацией email.
2. **Управление сообщениями** — создание шаблонов писем с темой и телом.
3. **Управление рассылками** — создание рассылок с динамическим статусом (Создана/Запущена/Завершена), автоматическим обновлением статуса при просмотре.
4. **Отправка писем по требованию** — ручная отправка через интерфейс с проверкой временного окна и сохранением истории попыток.
5. **Главная страница** — общая статистика (количество рассылок, активных рассылок, уникальных получателей) с кэшированием через Redis.
6. **Регистрация и аутентификация** — регистрация с подтверждением email, вход/выход, восстановление пароля.
7. **Персональная статистика** — отчёты по успешным/неуспешным попыткам отправки и количеству отправленных сообщений.
8. **Ролевая модель** — разделение на Пользователя (CRUD своих данных) и Менеджера (просмотр всех данных, блокировка пользователей, отключение рассылок).
9. **Management-команда** — тестирование системы с созданием тестовых данных, выполнением рассылок, формированием отчёта и самоочисткой.

## Нововведения технические (не предназначенные для глаз пользователя)

1. **Динамический статус рассылок** — метод `update_status()` в модели `Mailing` автоматически пересчитывает статус на основе текущего времени.
2. **Валидация дат** — проверка, что `start_time` не в прошлом и `start_time < end_time`.
3. **Пакетное создание попыток** — использование `bulk_create()` для эффективного сохранения истории отправок.
4. **Серверное кэширование** — встроенный LocMemCache для хранения статистики главной страницы с TTL 300 секунд (выбран для стабильной работы без внешних зависимостей, логика get/set идентична Redis)
5. **Клиентское кэширование** — заголовки `Cache-Control: private, max-age=60` для браузерного кэша.
6. **Инвалидация кэша** — сигналы Django (`post_save`, `post_delete`) автоматически очищают кэш при изменении данных.
7. **Разделение миксинов доступа** — `OwnerFilterMixin` для просмотра (менеджер видит всё), `OwnerOnlyMixin` для редактирования/удаления (только свои данные).
8. **Автоматическое создание профиля** — сигнал `post_save` на модели `User` создаёт `UserProfile` и назначает роль "Пользователь".
9. **Идемпотентная management-команда** — `test_mailing_system` можно запускать многократно без ошибок дублирования.
10. **Строгая типизация** — все методы аннотированы, проверка через `mypy` с `django-stubs`.

## Примечание к функциям

Все операции с кэшем происходят прозрачно для пользователя. В случае недоступности Redis, система автоматически переключается на прямой доступ к базе данных без прерывания работы приложения.

## Инструкция по настройке линтеров для данного проекта

Создайте файл с названием `.flake8` и в нём введите следующие настройки:
```ini
[flake8]
max-line-length = 119
ignore = E402, E251, E203
exclude = .git, .venv, __pycache__, venv
```
Вводите в файл pyproject.toml, если там не прописано, то пропишите следующие.
```
[tool.black]
# Максимальная длина строки
line-length = 119
# Файлы, которые не нужно форматировать
exclude = '''
(
  /(
      \.eggs         # Исключить несколько общих каталогов
    | \.git          # в корне проекта
    | \.hg
    | \.mypy_cache
    | \.tox
    | \.venv
    | dist
  )/
  | foo.py           # Также отдельно исключить файл с именем foo.py
                     # в корне проекта
)
'''


[tool.isort]
# максимальная длина строки
line_length = 119


[tool.mypy]
disallow_untyped_defs = true
warn_return_any = true
ignore_missing_imports = true
exclude = ["venv", "migrations"]
plugins = ["mypy_django_plugin.main"]

[tool.django-stubs]
django_settings_module = "config.settings"
```
И все зависимости что есть на данный момент будут прописаны.

## **Тестирование кодов**

### Запуск management-команды для тестирования системы:
Базовый запуск (с самоочисткой)
* python manage.py test_mailing_system

С параметрами
* python manage.py test_mailing_system --users=5 --clients-per-user=10 --messages-per-user=5 --mailings-per-user=3

Без самоочистки (для просмотра тестовых данных)
* python manage.py test_mailing_system --no-cleanup

С предварительной очисткой старых тестовых данных
* python manage.py test_mailing_system --cleanup-first

### Проверка работы кэширования:
python manage.py shell
```
from django.core.cache import cache
from django.db import connection
from django.test.utils import CaptureQueriesContext
from main.services import get_dashboard_stats, DASHBOARD_CACHE_KEY

cache.delete(DASHBOARD_CACHE_KEY)

with CaptureQueriesContext(connection) as ctx:
    print("Первый запрос:", get_dashboard_stats())
    print("Запросов к БД:", len(ctx.captured_queries))

with CaptureQueriesContext(connection) as ctx:
    print("Второй запрос:", get_dashboard_stats())
    print("Запросов к БД:", len(ctx.captured_queries))
```
Ожидаемый результат: первый запрос — 3 обращения к БД, второй — 0 (данные из кэша).
